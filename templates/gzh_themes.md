# 公众号板块与主题（gzh_themes）

公众号分三个固定板块，每个板块固定一个主题色。正文/封面统一用「青绿 aqua」基准色
书写，发布前用 [`scripts/gzh_theme.py`](../scripts/gzh_theme.py) 按板块切换主色。
中性色（标题 `#1a1a1a`、正文 `#333`、灰阶、封面黑色渐变）三套通用、不随主题变。

## 三大板块 → 主题色

| 板块 | 主题 key | 主色 | 适用内容 |
|---|---|---|---|
| **前沿科创** | `aqua` 青绿 | `#4ecdc4` | 前沿技术 / AI4S / 新工具新方法 / 产业突破（Biomni 属此） |
| **顶刊精读** | `orange` 橙 | `#ec7a26` | **已正式见刊**的 Cell/Nature/Science 系列单篇论文深读（预印本不收，见下方准入门槛） |
| **人物专访** | `indigo` 靛蓝紫 | `#6366f1` | 科学家 / 创业者 / 团队的人物访谈、故事 |
| **工具介绍** | `blue` 钴蓝 | `#2563eb` | 具体软件/数据库/在线工具的上手介绍、评测、教程 |

每套主题由 7 个「角色色值」定义（见 gzh_theme.py 的 `THEMES`）：
主色(hex)、主色(rgb，封面 rgba 用)、数据卡底、引语卡底、浅边框、虚线分隔、荧光高亮底。

## 选用规则

**按这篇属于哪个板块来定**（不是看选题表面关键词）：

- 报道"发生了什么新突破/新进展" → `前沿科创` → `aqua`
- 精读一篇具体顶刊论文 → `顶刊精读` → `orange`（**硬门槛：必须已正式见刊的 CNS 论文，预印本一律不进此板块**，见下方准入门槛）
- 以某个人/团队为主角的访谈故事 → `人物专访` → `indigo`
- 手把手介绍"某个工具怎么上手用"（软件/数据库/在线服务的用法、评测、教程）→ `工具介绍` → `blue`

> 前沿科创 vs 工具介绍：**报道一件新事**（如"Biomni 问世、拿了融资"）走前沿科创；
> **教你用一个工具**（如"Biomni 怎么装、怎么跑第一个分析"）走工具介绍。同一主题可拆两篇。

板块在写稿阶段确定，并在正文顶部放一个**板块标签**（见 gzh_style.md「板块标签」组件）。

## 用法

```bash
# 正文/封面用 aqua 基准色写好后，按板块切换主题：
python3 scripts/gzh_theme.py drafts/<date>_<slug> --theme orange
# 封面 HTML 变了色，重新生成 PNG：
python3 scripts/screenshot_cards.py drafts/<date>_<slug>/cover_gzh.html \
    --out drafts/<date>_<slug> --width 900 --height 383 --name cover_gzh --scale 2
```

切换是幂等的，可在任意两套主题间来回切。

## 板块特定结构：顶刊精读

> **准入门槛（用户既定，硬性，先过这关再谈其它）：**
> **「顶刊精读」严格只收「已正式见刊」的 CNS 论文** —— 即 **Cell / Nature / Science 三大主刊及其嫡系子刊**（Nature Medicine、Nature Biotechnology、Cell 系列、Science 子刊等），且论文**已正式发表、经过同行评审**、有正式期刊卷期/DOI。
> - **预印本（bioRxiv / medRxiv / arXiv）一律不进此板块**，哪怕是里程碑级工作。判断标准：主源是否为正式期刊页而非预印本服务器。
> - 预印本里的重大突破改走 **前沿科创（aqua）**「报道一件新事」的路子，并在正文/页脚明确标注「预印本，未经同行评审，结论以正式发表为准」。
> - 选题前先核实见刊状态（看主源 URL 域名、DOI、期刊名）；查不到正式见刊记录就**不选进顶刊精读**。
>
> **硬要求（用户既定，务必满足）：**
> 0. **前言必须点明"发表在哪本期刊"并放一张论文首页截图**（见刊佐证，用户既定）：正文最前面（板块标签之后、编者按附近）放一行发表信息——刊名 + 卷期/页码 + 见刊日期（如"发表于 Nature Medicine · 2025-06-06 · Vol.31, 2691–2702"），并配一张**期刊官网论文首页截图**（含刊头 masthead + 标题 + 作者 + 卷期行）。截图用 playwright 抓期刊页顶部：
>    ```python
>    # playwright chromium goto 期刊article URL → 截 masthead~citation 区域 → 存 images/figures/fig-N.jpg
>    ```
>    这张截图计入配图数（gongzhonghao 的 <img> 与 images/figures/ 数量仍要相等）。既证明"确已见刊 CNS"，也让读者一眼看到分量。
> 1. **先介绍文章背后的团队资料和履历**——通讯/一作是谁、单位、课题组研究主线与代表作、成员背景履历，放在最前面写扎实，这是第 1 节的重点，不能一笔带过；再往下走技术路线。
> 2. 顺序：团队背景与履历 → 技术路线 / 主要方法 → 创新点 → 结果与讨论呈现。
> 3. **图文结合**：必须配图，不能纯文字。
> 4. **图片高度清晰**：高分辨率，优先下原图大图（论文原图用 scripts/fetch_openfig.py 从 bioRxiv 抓），糊图不用、必要时放大修复。
> 5. **内容来源完全真实**：所有事实、人名、履历、数字、引语都出自真实文献或相关新闻，绝不编造；查不到就诚实写"未见/未查到"。

面向研究者（含博士生），顶刊精读**不走"科普5段"那套**，用学术精读骨架，分节标题固定为：

1. **作者团队与课题组脉络** — 通讯/一作、单位、发表刊与时间（配"头像+箭头"关系图）；
   再串出**这个组的研究主线**：把他们的往期代表作按时间连成一条线，点明本篇在脉络里的位置
   （是延续、是跃升、还是转向）。可配一张自制"课题组时间线"图。
2. **研究背景** — 领域痛点、这篇要解决什么、此前做到哪一步。
3. **研究方法** — 面向研究者要写**深**，不是一句"用了机器学习"带过。必须讲清：①具体技术路线
   （每步怎么做、关键参数/阈值/指标定义、**具体是哪种算法**）；②**为什么用这套方法**；
   ③**相比领域内其他方法的改进与优点**。样本量/队列/平台给全，**优先放一张论文原图**。
4. **创新点** — 相比前人新在哪（配自制对比/粒度图点透）。
5. **结果与讨论** — 主要发现（带数字）+ 作者自陈的局限/边界。
6. **专利与产业转化** — 这套方法/发现有没有申请专利、专利权人是谁（通常是大学）；作者有没有
   由此创办或关联的公司（spin-off）、有无商业化落地。**没有就诚实写"目前未见相关专利/仍属学术阶段"**。
7. **延伸讨论（可选）** — 方法学或行业趋势层面的一句思辨（如"为什么用经典 ML 而非深度学习"）。

配图：**优先"论文原图 + 自制解读图"混搭**——原图给可信度，自制图给易懂。
论文原图从**开放预印本(bioRxiv)**取（可署名转载）；正刊图有付费墙+版权，不用。
bioRxiv 有 Cloudflare 拦 curl，用 [`scripts/fetch_openfig.py`](../scripts/fetch_openfig.py) 过验证抓图：
```bash
python3 scripts/fetch_openfig.py <bioRxiv .full页URL> drafts/<slug>/rawfigs 9
```
抓到 F1/F2… 后挑有代表性的 resize 进 images/figures/，图注注明"论文原图（bioRxiv 预印本）"。

**调研指引：**
- **课题组脉络**：从论文 Intro 里作者**自引的前作**入手（顶刊引言通常会交代自己这条线做到哪）；
  再查通讯作者的 Google Scholar / 实验室主页 publications，挑 2-4 篇里程碑串成时间线。
  例：Wyss-Coray → 年轻血液/parabiosis（2005、2014）→ 器官衰老钟（2023 Nature）→ 细胞类型钟（本篇）。
- **专利**：用 Google Patents / lens.org / patents 检索"通讯作者名 + 关键词"或"机构(如 Stanford OTL)"；
  看专利权人(assignee)、有无作者创办的 spin-off 公司（衰老领域常见：Alkahest、BioAge、Vero 等）、
  是否已授权/商业化。查不到就明说"未见公开专利"，**不要编**。头像/公司信息同样标来源、注意版权。
